# Implementation contract

This file is the integration boundary for the initial implementation. The lead owns changes here.

## Runtime

- Every Docker image owns one folder under `deployables/` that is its complete build context: `portal/` (Dockerfile, Go module `abizeitbetrug/server` in `portal/server`, frontend in `portal/web`), `auth-mock/` (own Go module `abizeitbetrug/auth-mock`, package `authmock`, `users.yaml`), `backup/`, `caddy/`. No Dockerfile copies from outside its folder.
- A root `go.work` joins the two Go modules for development and tests only; portal tests may import `abizeitbetrug/auth-mock/authmock`, portal production code must not. Docker builds run without the workspace.
- Executable `deployables/portal/server/cmd/portal`, PostgreSQL via pgx. Listen `:8080` by default.
- Runtime env: `APP_ENV=development|production`, `ADDR`, `DATABASE_URL`, `PUBLIC_URL`, `UPLOAD_DIR`, `STATIC_DIR`, `AUTH_MODE=mock|oidc`, `OIDC_ISSUER`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET`, `SESSION_SECRET`, `BOOTSTRAP_ADMIN_SUBJECT` (explicit issuer subject, never display name), `BACKUP_STATUS_FILE`. `OIDC_BACKCHANNEL_URL` is an optional origin override only for development mock mode, allowing container requests to reach the provider while preserving its canonical issuer.
- Production rejects mock auth and insecure/missing configuration. Go serves built frontend from STATIC_DIR, fallback index.html only outside API/auth routes.
- `portal migrate` runs versioned migrations, `portal seed` inserts deterministic development fixtures only, `portal serve` starts HTTP (default). Fixtures include users and sample content/polls. No production data is seeded.
- `/healthz` liveness; `/readyz` database readiness.

## HTTP

JSON API under `/api/v1`. Errors `{ "error": { "code": "...", "message": "..." } }`. UUID IDs; RFC3339 UTC timestamps. List endpoints return arrays; ordinary mutations return the resulting object. Authentication failure 401, permission failure 403, missing/inaccessible private record 404, stale version/invalid transition/closed poll 409, validation 400, too large 413. All non-auth unsafe API requests require `X-CSRF-Token` obtained from GET /me. Cookies carry sessions, never browser token storage. Fetch uses same origin.

Types (snake_case JSON):

```
User { id, name, role: 'student'|'manager'|'admin', admitted: boolean, cohort_member: boolean, category_ids: string[], created_at: string }
Me { user: User, csrf_token: string }
Category { id, name, description, kind: 'idea'|'quote'|'memory'|'photo'|'person'|'proposal'|'words', repeatable: boolean, ongoing: boolean, closes_at: string|null, status: 'draft'|'open'|'closed', allow_self_vote: boolean, all_people: boolean, max_choices: number, options: PollOption[], my_option_ids: string[], my_words: string[], my_option_id: string|null, version: number, created_at, opened_at: string|null, ballot_count: number|null, participation: {voted: number, eligible: number}|null }
Attachment { id, filename, mime_type, size_bytes, url, preview_url, caption }
Submission { id, category_id, author_id, author_name, title, body, context, status: 'pending'|'accepted'|'rejected'|'withdrawn', version: number, created_at, updated_at, attachments: Attachment[] }
Revision { id, version, actor_name, title, body, context, status, created_at, attachments: Attachment[] }
Correction { id, submission_id, author_name, body, created_at, resolved: boolean }
PollOption { id, label, user_id?: string }
PollResult { option_id, label, count: number }
BallotAudit { user_id, user_name, option_id, option_label, ballot_id: string|null, created_at }
AuditEvent { id, actor_name, action, entity_id, created_at }
```

Endpoints:

- `GET /me` -> Me. `POST /auth/logout` (outside prefix) logs out with CSRF header, then client reloads login.
- `GET /auth/login` redirects to the external OIDC provider; `GET /auth/callback` exchanges a one-use authorization code with PKCE and verifies the signed ID token, issuer, audience, expiry and nonce before creating the session. Both auth modes use this same consumer flow. The portal exposes no identity-list or mock-provider routes.
- Development only: the separate `auth-mock` service at `http://localhost:9090` reads `deployables/auth-mock/users.yaml` (`users: [{name, display_slug}]`; the OIDC subject is a UUIDv5 of the slug under a fixed namespace, never configured by hand). Its `/authorize` page lists every configured identity; `POST /authorize` selects one. Discovery, `/keys` and `/token` implement OIDC authorization-code flow with S256 PKCE and short-lived RS256 JWTs. Exact callback allowlists prevent open redirects. The provider has no database access or portal role claims. Seeded accounts use the subjects derived from their slugs and retain local fixture permissions; new slugs become pending local accounts. The provider refuses to run unless `APP_ENV=development` and is absent from production Compose.
- A Category (UI term: Sammlung) is the only collection entity. `kind` selects contribution content (`idea`, `quote`, `memory`, `photo`) or ballots (`person`, `proposal`, `words`). Persisted `repeatable` is independent of kind: contribution collections allow one record per author across all statuses when false, multiple when true; ballot collections retain one changeable current selection when false and allow independent ballot entries when true. `ongoing` is independent of both: true means manual closing, false requires a future `closes_at`. All kinds support draft/open/closed. Open collections become effectively closed at the deadline; reads and writes enforce this without a scheduler. No date such as June 2027 closes anything implicitly.
- `GET /me/ballots` -> `MyBallot[] {id,category_id,category_name,category_kind,category_status,created_at}`. Every admitted role receives only its own current ballot entries. Multi-option and word selections form one entry per ballot key; repeatable casts remain separate, nonrepeatable replacements remain one current entry, and retries add none. Entries include closed and hidden collections, with effective deadline status and latest current entry timestamp, sorted newest first with stable category/key ties. No choices, voter identities, totals or audit history are returned. Hidden entries are displayed without a collection link.
- `GET /categories` -> Category[]. Students see no drafts. `ballot_count` and `participation` only for editors, null for students and contribution kinds. `ballot_count` counts distinct voters across all preserved current ballots. `participation.voted` counts only current ballots from currently admitted cohort members; `participation.eligible` counts the same population, regardless of role. Both participation counts use one database snapshot, so revoking admission or cohort membership excludes that person from both without deleting ballots or named history. Zero eligible people means zero participation. The Redaktion dashboard shows voted/eligible with a proportional gray-to-green bar and rounded percentage. `my_option_ids` contains only the viewer’s current selections (empty if none); legacy `my_option_id` is the first in canonical ID order, or null.
- `POST /categories` `{name,description,kind,repeatable?,ongoing?,closes_at?,allow_self_vote,all_people?,max_choices?,options:[{label,user_id?}]}`. Admins and managers create every kind; manager creators receive a grant atomically. Omitted repeatable defaults true for contribution kinds, false for ballots. Omitted ongoing defaults true. Ongoing collections store closes_at null; bounded collections require a future timestamp. Contribution kinds start open if ongoing, draft otherwise; ballots start draft. Contribution kinds require empty options and max_choices 1. Words polls require empty options and default max_choices to 3; other ballots require 2–500 unique options unless person/all_people mode builds them from admitted cohort members. Person options reference admitted members; person polls default all_people true and freeze their roster on first opening. Option ballot kinds allow max_choices 1–500.
- `PATCH /categories/{id}` same fields plus `version`; stale version 409. Only canEdit (admin or granted manager). Omitted repeatable, ongoing and closes_at preserve stored settings. Repeatability and ongoing are fixed after creation. A sparse `{version,closes_at}` PATCH changes a bounded ballot’s deadline to a future instant in draft, open, closed or hidden state, under the same category lock, grant and stale-version checks. It preserves the complete definition, option IDs, votes, history, opened_at and stored status. Extending an automatically expired stored-open poll makes it open again; manually closed and hidden polls keep their status. Contribution deadlines remain fixed. Omitted or unchanged deadlines retain their exact stored precision and may be expired for unrelated edits. Contribution definitions remain editable within their content family. Ballot definitions remain editable only before first opening (draft with opened_at null), even after hiding; ballot kinds may change within their family.
- `POST /categories/{id}/status` `{version,status}` for every kind; admin or granted manager. draft->open, open->closed, open/closed->draft. Expired collections cannot reopen. Person/proposal ballot opening requires two options; word ballots use free word entry and refreshes an all_people roster only on first opening; contribution opening has no ballot-option requirement. Hiding preserves content, votes, history and opened_at.
- `DELETE /categories/{id}` `{version}` admins only -> 204. Missing poll 404, stale version 409, contribution kind 400. Under the category row lock, atomically removes current ballots, named ballot history, options, category and its manager grants; records `poll.deleted` in generic audit without names or choices. The UI confirms permanent deletion and its ballot/history removal before submitting.
- `GET /submissions?category_id=&status=&q=` -> Submission[]. Students automatically restricted to own; editors all. Search q matches title, body and author name. `POST /submissions` `{idempotency_key,category_id,title,body,context}` creates pending (UI: Eingereicht). Collection has no review/release gate; all contributions remain visible to authorized readers before post-collection moderation. Submissions (create and category edit) require a contribution-kind category, otherwise 400. `GET /submissions/{id}` -> Submission.
- `PATCH /submissions/{id}` `{version,title,body,context,category_id}`. Author only while pending, including admins/managers editing their own contributions; editorial roles cannot change other authors’ text or photos. Redaktion mode exposes no content mutations, including on own contributions. Revision and audit transaction.
- `POST /submissions/{id}/status` `{version,status}`. Author pending->withdrawn. Editors pending->accepted/rejected, accepted/rejected/withdrawn->pending. No other transitions.
- `GET /submissions/{id}/revisions` -> Revision[]. Same read permission as submission.
- `POST /submissions/{id}/attachments` multipart `file`, `version` field. `DELETE /submissions/{id}/attachments/{attachmentID}` with `{version}`. Return Submission with incremented version. Same mutation permissions as text; originals immutable. `GET /attachments/{id}` original and `/attachments/{id}/preview` authorized image response.
- `GET /submissions/{id}/corrections` -> Correction[]. `POST /submissions/{id}/corrections` `{body}` author on locked contribution, or editor with category grant on any status (editorial annotation). Notes are separate from the original and readable by its author and editors. Editors without grants have read access only. `POST /submissions/{id}/corrections/{correctionID}/resolve` editorial permission.
- `PUT /categories/{id}/ballot` `{option_ids:string[],ballot_id?:uuid}` -> `{option_ids,option_id,ballot_id?}`; legacy option_id remains supported exclusively of option_ids. Ballot kinds only, open and unexpired, active admitted cohort members. Validate 1–max_choices distinct options and self-vote restrictions atomically under category lock. Nonrepeatable polls replace the full current selection as before. Repeatable polls require a client ballot_id and append an independent entry; same key and selection replays successfully without extra rows/audit, changed payload conflicts. The viewer sees only the latest entry selections. Results include all entry choices; ballot_count and participation still count distinct voters. Only admins read named ballot history.
- `GET /categories/{id}/results` -> PollResult[] editors only. `GET /categories/{id}/audit` -> BallotAudit[] admins only, includes changes. Every changed selection writes a complete snapshot grouped by `ballot_id`; legacy single-choice audit rows have null ballot_id. Replaying an unchanged nonrepeatable selection or the same repeatable ballot key does not add history; a new repeatable key intentionally adds an independent entry. Never in generic category payload. There are no `/polls` routes.
- `GET /roster` -> `{id,name}[]` admitted cohort only (minimal candidate names required for polling).
- `GET /categories/{id}/export?status=all` -> ZIP, editors all contribution kinds (ballot kinds 400). Default status is 'all', including pending, accepted, rejected and withdrawn originals; explicit status filters remain available for later moderation. CSV and originals plus JSON manifest. No ballots.
- Admin: `GET /admin/users` -> User[]; `PATCH /admin/users/{id}` `{name,role,admitted,cohort_member,category_ids}`. Do not allow removal of the last admitted admin. `DELETE /admin/users/{id}` -> 204; 404 unknown id; 409 `self_delete`, `last_admin`, or `has_content` (any submissions, revisions, corrections, ballots, ballot audit, audit events or poll-option links; block access instead). Deletes sessions and writes `user.deleted`.
- Admin: `GET /admin/audit` -> AuditEvent[] (recent 200); `GET /admin/status` -> `{backup_last_success: string|null, backup_stale:boolean, upload_bytes:number}`.

## Ownership and quality

- Backend agent owns deployables/portal/server/ and deployables/auth-mock/ Go code, migrations, backend tests. UI agent owns deployables/portal/web/. Ops agent owns ops/, Dockerfiles, compose files, Makefile, .github/workflows/.
- Root owns docs/, README, .gitignore, integration fixes. Shared changes coordinated before edits.
- Every data read enforces role/ownership, including files, revision history, exports and poll data. Managers read all submissions and annotate only granted categories. Only authors mutate pending original submissions and their attachments. Category/poll administration remains grant-controlled. Pending author edits preserve history. No audit or system log stores credentials.
- Production never enables mock login. Mock seed identities are deterministic. Admin privileges remain local to the application.
- Backend integration tests use TEST_DATABASE_URL and a disposable isolated database/schema; tests must skip clearly if unavailable, never touch real data. UI includes component tests and Playwright journeys configured for a running seeded app.
- Database + immutable files are backed up as one recovery set. File removal is soft deletion; no physical GC in v1. All acknowledged uploads are finalized on disk before database references commit.

## Migration 004: polls become categories

Each poll becomes a category row with the same id (title -> name, kind, status, allow_self_vote, version, created_at, opened_at). Existing repeatable categories get status `open`, version 1. `poll_options`, `ballots`, `ballot_audit` keep their rows and reference `categories`. Every user whose `category_ids` contained a poll's former category also gets the poll's id. The `polls` table is dropped. Audit actions keep their names (`poll.*` for single-answer operations, `category.*` for definitions).

## Redaktion collection workspace

Sammlungen is the shared collection workspace: every editor can create all seven kinds and edit definitions they manage. Admins additionally assign manager grants in the same creation/edit form, including permissions in the form for opened or closed ballots whose definitions remain locked. Assigned editors can edit bounded ballot deadlines in that same form after publication, using a German calendar and local time picker; admins can also edit manager grants. The duplicate Verwaltung collection page redirects to `/sammlungen`. Verwaltung navigation contains only people and activity and is available only to admins in Redaktion; direct Verwaltung bookmarks activate and remember Redaktion mode. Redaktion uses neutral gray chrome, white reading panels, and cobalt accents for actions, selection and focus; Schüler mode retains the yeargroup palette. Every contribution collection opens a searchable list of all its submissions, with a read-only reader at `/redaktion/beitraege/:id`. The reader preserves originals, photos and revision history and allows optional category-granted annotations; no accept/reject/release action is required during collection. Ballot collections show read-only options and aggregate results in Redaktion; voting stays in Schüler mode. Existing status endpoints and historical statuses remain available for later moderation, without changing or automatically releasing existing data.

## Migration 005: people poll selections

Existing candidate sets, current votes and named history are preserved. Adds `all_people` (false for migrated rows), `max_choices` (1), a three-column ballot primary key, and nullable `ballot_id` on historical snapshots. All-person candidate snapshots are refreshed on opening; previously opened definitions remain immutable even after hiding. No named choices are included in generic audit events.

## Migration 006: proposal poll selections

Allows choice polls (`proposal`) to configure the same 1–500 selection cap as person polls. Existing caps, options, current votes and audit history stay unchanged. Repeatable categories retain cap 1; all_people remains exclusive to person polls. Both ballot UIs show removable selection chips. Search appears for at least ten listed choices (including candidate setup) and stays hidden for shorter lists. The cap uses circular minus/plus buttons and a large native number input that gains field styling only on focus.

Independent collection controls: all seven classes remain selectable independently of the Wiederholbar and Fortlaufend switches. One-off photo/text collections use the contribution reader, author editing, attachments and ZIP export. New create/move actions require an open unexpired target and an unfilled one-off author slot; idempotent retries and same-record pending edits/uploads remain available. Both switches are fixed once created; bounded ballot deadlines remain editable after saving and first opening. Contribution deadlines stay fixed.
## Word portraits: Abi in drei Worten

`words` is a ballot collection kind using the existing draft/open/closed lifecycle and immutable-after-first-opening definition. Creation accepts empty `options`, defaults `max_choices` to 3, and allows an explicit 1–500 word limit. The generic category payload always exposes `options: []` for this kind. `my_words` contains only the viewer's current original words, with their existing own ballot IDs; no other words, counts, or moderation data reach students. Existing poll counts and participation count voters, regardless of their word count.

`PUT /categories/{id}/ballot` accepts `{words: string[]}` exclusively for word portraits (never mixed with option fields). Each word is trimmed, normalized to Unicode NFC and lowercase, and must be one token of 1–64 Unicode codepoints without whitespace or controls. Empty, duplicate normalized, and over-limit selections are rejected atomically. Nonrepeatable replacements remove previous current counts; reordering equivalent words adds no history. Repeatable word entries require ballot_id and use the same retry guarantees as option ballots. Original normalized words remain immutable in poll options and admin-only named ballot snapshots.

All editorial roles can read aggregate results, anonymous original-word tallies, and CSV, including managers without a category grant. Students cannot read any of these, even after closing. `GET /categories/{id}/words` returns `WordEntry[] {option_id,word,label,excluded,count,version}` with current original-word counts and no voter identity. `PATCH /categories/{id}/words/{optionID}` accepts `{version,label,excluded}` and requires an admin or the category's manager grant. It checks the moderation version under the category lock, returning 409 on stale updates. Exclusion is reversible; editing an effective label corrects a word, and matching effective labels merge words. Neither action changes the original word or named history. Results count each ballot entry at most once per effective label (one current entry per voter in nonrepeatable polls), omit excluded words and zero counts, and reuse `PollResult[]`.

`GET /categories/{id}/words/export` downloads a UTF-8 CSV of those same effective labels and counts, with formula-safe cells and a fixed download filename. The React word cloud renders text nodes in a responsive weighted layout without HTML insertion or an additional dependency. Student entry uses removable lowercase chips. Redaktion displays toggleable original-word chips and correction/merge controls; managers with read access see the cloud and tallies without mutation controls. Named history remains admin-only.

## Photo collections and choice chips

Choice (`proposal`) ballots render every option as a wrapping toggle chip with a pressed state; selection caps, search thresholds, eligibility, repeatability and ballot privacy are unchanged.

Photo collection creation requires `POST /submissions` multipart with `category_id`, `idempotency_key`, exactly one `file`, optional `title` (defaults to filename), optional `context`, and optional `caption`. The first validated JPEG, PNG or WebP image and its submission commit together; JSON photo creation and nonempty photo `body` are rejected. Same-key/same-payload retries return the existing submission; changed payload conflicts. Additional images use the existing attachment upload endpoint, up to ten images total, each at most 20 MiB/24 megapixels. Photo edits and category changes must retain an image and an empty body; existing legacy empty photo entries remain readable and can receive uploads. A populated non-photo category cannot become photo unless every contribution already meets these constraints. Deleting a photo contribution's final image is rejected.

Every attachment has an optional caption represented as a string (empty by default), limited to 2000 Unicode codepoints. Uploads accept multipart `caption`; `PATCH /submissions/{id}/attachments/{attachmentID}` accepts `{version,caption}` and returns the version-incremented Submission. Only the pending original's author can change captions. Caption edits, uploads and removals preserve attachment metadata in revision snapshots and captions in ZIP export manifests; old revisions have empty attachment snapshots. Migration 009 adds caption storage and revision attachment snapshots without changing existing contributions or files.

Photo collections use a responsive loose album layout with rounded images at natural aspect ratios. Students see only their own images, while Redaktion sees all originals and captions with no editing controls.

## Student contribution overview

The student dashboard combines own text/photo contributions and all own current poll entries under “Deine Beiträge”, newest first, with a maximum of ten displayed rows. Photo batches remain grouped by collection before the row limit. “Alle ansehen” opens `/beitraege`, an unlimited combined list with collection-name search and an “Abgestimmt” status filter. Unanswered polls do not count as contributions. The separate “Erledigte Sammlungen” section is removed.
